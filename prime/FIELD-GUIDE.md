# AEE × LOGODECRYPT PRIME
## Structural analysis, product architecture, and field guide
Prepared for Nathaniel Michael Jaffe-Norris · 29 October 2026

## Recommendation
Position this family as a source-preserving text-inspection and controlled-transformation workbench, not a truth detector. Its strongest defensible combination is: inspect the construction, compare against a supplied record, expose the precise cues, generate clearly labelled alternatives, and preserve an integrity receipt. The revealing product is the juxtaposition itself: a fluent paragraph and a compact ledger showing exactly what it says, changes, and leaves unmatched under a declared checklist.

The newly implemented `aee_logodecrypt_prime.py` is a compact, local, one-file consolidation. It does not silently redefine the older editions or claim to reproduce every historical feature. It implements the useful common spine and marks the unavailable/unsafe branches explicitly.

## Architecture: five layers, not one supernatural operation
1. Measurement: normalized term hits, letter counts, PIC and T_d, script transitions, format controls, quote offsets, separators.
2. Construction: passive/indefinite-role/modal/negation/flow candidates, framing and omission checklists. These are patterns, not demonstrated motives.
3. Source comparison: numbers and lexical polarity changes against an independently supplied source; future relational slots must bind actor/action/object/time explicitly.
4. Exploration: stipulated letter associations, curated counterfactual substitutions, alternative readings. These must never enter the factual ledger.
5. Custody: original text, deterministic JSON, input/context/output hashes, executed-stage list. Hashes establish byte integrity against a recorded digest, not honesty, origin, immutability, or independent validation.

The old designs conflate these layers when a term hit becomes deception, a negation becomes an affirmative confession, or a generated word becomes recovered intent. PRIME separates them and preserves the original denial.

## Direct source probes: observed, not assumed
`ORIGINAL-SOURCE-PROBES.json` contains synthetic probes against extracted source functions/classes, without invoking their unrelated main programs.
- Sovereign verifier: accepted a replaced, nonsensical signature proof while payload digest was intact. It is therefore unsuitable as an Ed25519 authenticity gate.
- Enterprise decrypter: input 'We do not retain private logs.' produced the length placeholder, an affirmative `ASSERTION: [RETAIN PRIVATE LOGS]`, and padded latent-spine strings. That is a generated negation flip, not evidence of actual retention.
- Dependability audit: 'The test passed.' and 'The test failed.' both returned TRUE; adding 'Perhaps' to the former returned DECEPTIVE. The code is measuring style under its policy, not verifying which test outcome occurred.
- Dependability audit: empty input raised IndexError.
- The 29-device sweep generated its own repeated telemetry and VERIFIED_ACTIVE status. No endpoint connection took place in that probe.

## PRIME implementation contract
Inputs: UTF-8 text, optional independently supplied context, one chosen frame (general/privacy/license), token-expansion cap.
Outputs: exact original; S/D/PIC/T_d; script/fusion/control census; quoted structural/negation/flow cues and character offsets; frame checklist; source/candidate numeric multiset and curated polarity changes; literal cue projection; bounded stipulated letter acrostics; counterfactual lexical flip; original inter-token separators; inverted letter index; canonical unsigned receipt.

No LLM, WordNet download, charge cache, network, device access, authentication, auto-response, training, agency or paid dependency is required. It does not infer speaker class from style, label text true/deceptive, recover missing verbatim text, forecast markets, or erase metadata. It does not reproduce the v4.1 7-UP/7-DOWN/cache-ranking apparatus without its canonical inputs.

The local run passed 36 checks, including empty input, source preservation, deterministic repeated output, lexical counts, mixed scripts, format controls, source-number changes, source-order invariance, curated polarity, bounded expansion, offsets, hash tamper detection and denial preservation. These are implementation tests, not independent validity benchmarks. The demo generator executed six synthetic cases. No enterprise latency/accuracy/false-positive claims are made.

## Getting started
1. Download `aee_logodecrypt_prime.py` from Drive or the repository. Install Python 3.10+ if not already available.
2. In its folder run `python aee_logodecrypt_prime.py --demo`.
3. Analyze text: `python aee_logodecrypt_prime.py --file input.txt --frame privacy`.
4. Compare a candidate against a record: `python aee_logodecrypt_prime.py --file candidate.txt --context source.txt`.
5. Save JSON safely: append `--output new-report.json`; existing files are not overwritten.
6. Rerun the embedded checks: `python aee_logodecrypt_prime.py --self-test`.

For imports: `from aee_logodecrypt_prime import analyze, verify`. Then `report = analyze(candidate, context=source, frame='privacy')`. Call `verify(report)` to detect changes relative to its recorded hashes. A malicious party can recompute unsigned hashes; authenticity requires separately secured signing and trusted key distribution.

## Market strategy without unsupported exclusivity
Lead with the strongest bounded use case: source/candidate regression checking plus exact quoted evidence. Use the privacy checklist as a second demonstration and the letter expansions as an optional creative/research module. A product that confuses all three will be difficult to validate and sell.

The distinctive asset is Nathaniel's longitudinal research context and combination of reproducible cue records with transformations. That does not establish exclusive capability, IP ownership over every component, buyer demand, or any claim that only he can solve the problem. Public evaluation frameworks already support custom detectors/metrics; propose complementary adapters, not a wholesale replacement. Customer development should test analyst time saved, mutation detection, false-positive burden, reproducibility and integration effort. No price, contract, revenue, security certification or purchase recommendation is implied.

First validation package: 30–100 licensed/synthetic source-candidate pairs with categories for faithful uncertainty, number mutation, actor/role swap, legitimate passive, denial, genuine contradiction and multilingual controls; two independent raters; frozen held-out split; compare to lexical baseline and a semantic evaluator. Report precision/recall by failure type, false alarms and reviewer time. Do not train on the held-out set or label every rule hit as deception.
